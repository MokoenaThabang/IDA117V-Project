# Stakeholder interview guide

This guide is a list of questions for a municipal service-delivery stakeholder. No interview has been conducted. Nothing in this file is a stakeholder answer, a department finding, or an approval.

Ask the questions in plain language. Record the date, the role of the person, and whether they agree to be quoted. Do not record a resident's name, address, or notification id. Do not treat the answers as a reason to change the frozen model until they are written down and reviewed.

1. When a request is first logged, which of these are known: complaint type, suburb, ward, subcouncil, and work centre?
2. Is a work centre assigned at logging, or only after the request has been received? Is that assignment time stored?
3. Does a seven-day completion have an operational meaning for the service, or is that cutoff only a project rule?
4. What should a reviewer do with an estimate of Resolved Slow or Unresolved? What should they not do?
5. Which request types or stored location codes are too messy to show as an area comparison?
6. What would make this estimate unsafe to put in front of staff?
7. Is there a person who should review a later version before anyone relies on it?

Until those answers exist in a dated note, the project has no stakeholder validation.
